04Where the documents disagree with the code

Four of these. The code wins every time, because the code is what runs.

CONFLICT 1A still marked 'peer' is silently fatal
SKILL.md
The sunday-content-review assignment table has no line that produces 'peer' for a Static. It wrote 'peer' anyway on 3 of the 11 UGH stills it created on 2026-11-01.
Code
peer is assignable, so step 2 honours it and the format default at step 5 never runs.
Effect: the server sees the row every two hours, correctly identifies it as the Peer's, and skips it forever. Nov 6 and Nov 9 both died this way. The eight siblings from the same batch marked automation all posted.
CONFLICT 2The documents route carousels to the Builder; the code routes them to the Peer
SKILL.md
builder-morning-run:69 claims "carousels in any project". peer-morning-run:71 agrees. Charter §2c agrees.
Code
formats.ts:58 matches carousel in the Peer regex. An unassigned carousel is reported as PEER'S.
Effect: three documents say one thing and the server does the opposite. A carousel nobody assigns goes to the Peer — a local run — not the Builder.
CONFLICT 3'builder' is written by one run and discarded by the server
SKILL.md
sunday-content-review:89 — stills, carousels, Story poll backgrounds -> 'builder'
Code
formats.ts:107 — ASSIGNABLE = ["automation","peer","glenn"]. 'builder' is not in it, so the value is thrown away and the format decides (Glenn, 2026-09-12).
But also
builder-morning-run:76 does claim rows marked 'builder'.
Effect: a still marked 'builder' is claimed by both the server (via the format default) and the local Builder run. It usually works by accident, because the format default is the right answer anyway — but the value written in the column is a fiction, and two runners believe they own the row.
CONFLICT 4The Sunday review writes assigned_to at all
The shape
Every value that run can write falls into one of three cases: it matches the format default (a no-op), it is 'builder' (discarded), or it overrides the default (the only case that changes anything).
Code
The format default at steps 4–5 is already correct for every row type on the calendar.
Effect: the one case where the column has real force is the one case where it is always wrong. A planning run has no information the format does not already carry.
AGREESStory polls → Glenn
Everywhere
Charter §2c-1, both morning runs, the Sunday review and isStoryPoll() all say the same thing, and the code enforces it at step 1 ahead of every other rule.
This is what a rule looks like when it is written once and enforced in code. It has never misrouted a row.

06What fixes it

  1. The Sunday review stops writing assigned_to on anything but a deliberate exception. Leave it NULL and the format default routes every row correctly, with no second copy of the rule to drift. This removes conflicts 1, 3 and 4 at once.
  2. Delete the 'builder' target from the assignment table. The server discards it; only the local Builder run reads it, and that run can find its own work by format.
  3. Reconcile the carousel rule. Either the code moves carousels to the Builder or the three documents stop claiming them. One of the two has to give, and the code is what runs.
  4. Say in one line, in each file, that _shared/formats.ts is the routing authority — the same way Story polls are already settled. Any ownership rule restated in prose is a rule that will drift.
